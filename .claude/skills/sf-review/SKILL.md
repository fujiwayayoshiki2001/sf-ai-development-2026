# 統合コードレビュー

このスキルは、指定されたファイル（または最近変更されたファイル）に対して、
複数の観点から包括的なレビューを実行するオーケストレーターです。

各観点のレビューは独立したスキル (review-security, review-naming 等) が
担います。このスキルはそれらを **順番に呼び出し**、結果を統合して
統一フォーマットで出力する役割を持ちます。

## 引数

`$ARGUMENTS` にはレビュー対象のファイルパスが入ります。
省略された場合は、最近変更されたファイルを対象にしてください。

例:
- `/sf-review` → 最近変更されたファイルをレビュー
- `/sf-review force-app/main/default/classes/LeadController.cls` → 指定ファイルをレビュー

## 実行手順

### Step 1: 対象ファイルの判別

引数で指定されたファイル `$ARGUMENTS` を読み込み、ファイルタイプを判別してください。

```
[判別ロジック]
- *Test.cls → テストクラス → "test" モード
- *.cls → 通常の Apex クラス → "standard" モード
- *.trigger → Apex トリガー → "standard" モード
- *.flow-meta.xml → Flow → "flow" モード
- *.js（LWC）→ LWC → "lwc" モード
```

引数が省略されている場合：
1. git status で変更されたファイルを確認
2. 最も最近変更された Apex/Flow/LWC ファイルを対象にする
3. ユーザーに「ファイル名: XXX をレビュー対象にしました」と通知

### Step 2: モード別のスキル呼び出し

判別したモードに応じて、以下のスキルを **この順番で** 呼び出してください。
各スキル (`.claude/skills/review-XXX/SKILL.md`) を読み込み、その指示に従って
レビューを実行します。

#### "standard" モード（通常の Apex クラス・トリガー）

```
[フェーズ 1: サニティチェック（致命的問題）]
1. review-governor-limits  (ガバナ制限違反)
2. review-security         (セキュリティ脆弱性)
3. review-error-handling   (エラー処理)

[フェーズ 2: 品質チェック（保守性・可読性）]
4. review-bulkification    (バルク化対応)
5. review-naming           (命名規則)
6. review-best-practices   (その他のベストプラクティス)
```

#### "test" モード（テストクラス）

```
1. review-test-quality     (テスト品質)
2. review-naming           (命名規則)
3. review-best-practices   (その他のベストプラクティス)
```

#### "lwc" モード（LWC）

```
1. review-lwc              (LWC 品質: エラー処理・ライフサイクル・LDS 等)
2. review-security         (セキュリティ: innerHTML・ハードコード ID 等)
3. review-naming           (命名規則: コンポーネント名等)
```

#### "flow" モード（Flow）

Flow 用の専用スキルはないので、以下の観点で総合的にレビューしてください：
- バルク化（ループ内 Update Records ではないか）
- フェイルパス（Fault Path）の有無
- ハードコーディング
- 命名規則

### Step 3: 各スキルの実行

各スキル実行の流れ：

1. `.claude/skills/review-XXX/SKILL.md` を読み込む
2. スキルの指示に従って、対象コードをレビュー
3. 検出された問題を内部的に記録（最終レポートで統合するため）
4. 次のスキルへ

**重要**: 各スキルの実行中は、そのスキルの観点に集中してください。
他の観点の問題が見つかっても、後続スキルの担当領域なので無視してください。

### Step 4: 統合レポートの出力

すべてのスキル実行後、以下の統合レポートを出力してください。

## 注意事項

### スキル実行時の注意

- 各スキルは独立して動作させる
- スキルの結果は内部的に保持し、最終レポートで統合する
- 重複する問題（複数スキルで同じ問題を検出）は、最も適切なカテゴリにまとめる

### レポート出力時の注意

- 高優先度の問題を最初に表示
- 各問題には必ず具体的な改善案を含める
- ファイル名・行番号を明示して、すぐに修正できる状態にする
- コードブロックは ```apex（または ```javascript）で囲む

### 研修教材としての配慮

- このプロジェクトは研修教材なので、意図的に「悪いコード」が含まれている可能性がある
- 検出された問題が「仕込まれたもの」かどうかは判断しなくて良い
- 受講者の学習促進のため、改善案だけでなく「なぜそうすべきか」も説明する
- 必要に応じてヒントだけ示し、答えは受講者に考えさせる選択肢も提示する

### スキルが見つからない場合

`.claude/skills/<スキル名>/SKILL.md` が存在しない場合：
- そのスキルはスキップする
- スキップしたスキルを最終レポートに記載する
- 「<スキル名> のスキルが未配置のため、その観点はレビューできませんでした」と通知する

## 実装サンプル

仮の実装イメージ（Claude Code として動くときの参考）：

```
1. ユーザー入力: /sf-review LeadController.cls

2. ファイル読み込み:
   - /workspace/force-app/main/default/classes/LeadController.cls を読み込む
   - ファイルタイプ: 通常の Apex クラス → "standard" モード

3. スキル呼び出し (順次):
   - review-governor-limits を実行 → 問題A, B を検出
   - review-security を実行 → 問題C を検出
   - review-error-handling を実行 → 問題D, E を検出
   - review-bulkification を実行 → 問題F を検出
   - review-naming を実行 → 問題G, H, I を検出
   - review-best-practices を実行 → 問題J を検出

4. 統合レポート出力:
   - 合計 10 件の問題を検出
   - 優先度別・カテゴリ別に整理
   - 改善案を提示

5. 次のアクション提案:
   - /refactor で自動修正
   - 高優先度から手動修正
```

このように動作してください。
